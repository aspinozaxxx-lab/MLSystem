## Validation data invariants

- `real_train` uses deterministic `_split_train_val_matches(..., seed=seed)` unless a prepared dataset manifest exists.
- Train batches are shuffled; validation batches are not shuffled.
- Train augmentations are applied only in the train loop.
- Validation uses `model.eval()` and `torch.no_grad()`.
- Validation metrics now reset accumulators each epoch.
- Source-of-truth pixel metrics are micro metrics from accumulated TP/FP/FN/TN over all validation pixels.
- The threshold is logged as `metrics.threshold` and `val/threshold`.

## Основная найденная проблема

До исправления `train_model` считал `dice/iou/precision/recall/f1` на каждом batch и затем публиковал простое среднее по batch. Для разреженного класса «вырубки» это нестабильно: batch без positive support и batch с несколькими объектами получают одинаковый вес. Из-за этого `val/pixel_f1`, `val/iou` и производные значения могли не соответствовать единой confusion matrix по всей validation выборке.
