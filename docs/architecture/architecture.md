# Основной интерфейс приложения - FastAPI. Реализуется функционал для:
1. Проведения экспериментов. 
2. Запуска инференса с использованием обученных сетей.

## Проведение экспериментов

# Проведение эксперимента состоит из:
1. Подготовки датасета (модуль dataset_preparing) - проверка входных данных, формирование val и train списков снимков.
2. Нарезка тайлов (модуль tile_preparation) - по готовомому описанию датасета из dataset_preparing готовитбатчей с тайлами и анотациями для обучения. На этом этапае добавляется аугментация. 
3. Обучение модели - прохождение эпох обучения моделей по полученным из tile_preparation батчам.

# Оркестратор (train_pipeline)
Организует прохождение эксперимента по всем стадиям, хранит промежуточные состояния и создает lifecycle/status/stage summary. Любую MLflow-запись выполняет только через `mlflow_adapter`: `train_pipeline` не решает, какие метрики попадут в MLflow UI, и не владеет MLflow logging policy.

# Оркестратор псевдоразметки (inference_pipeline)
Организует создание псевдоразметки через InferenceEngine: создает run, хранит trace/status/log/progress, запускает worker, вызывает InferenceEngine через API/client и фиксирует итоговые артефакты. Не выполняет tiling/vectorization/postprocess сам.

# Вспомогательные модули:
* Работа с MLFlow (mlflow_adapter) - единственный владелец MLflow access и MLflow logging policy; предоставляет интерфейс для логирования экспериментов, а так же их просмотра.
* Модуль `dataset_preparing` — проверка входных данных, scene matching, train/val split, dataset manifest.
* Модуль `metrics` — расчёт pixel/object metrics и metric artifacts.
* Модуль `storage` — единый доступ к local/S3 IO.
* Модуль `settings` — загрузка runtime config MLSystem.
