# Правила модулей MLSystem

## Определение

Модуль MLSystem - отдельная папка в `mlsystem/src`, которая владеет одной областью ответственности.

Примеры модулей:

- `tile_preparation`;
- `pipeline_runner`;
- `pipeline`;
- `mlflow_adapter`;
- `models`;
- `metrics`.

## Публичный API

- Если модуль используется извне, он должен иметь `facade.py` или явно описанный public entrypoint.
- Внешний код использует только public API.
- Внутренние функции не импортируются из соседних модулей, кроме тестов.
- Изменение public API требует архитектурного решения и согласования с пользователем.
- Backward compatibility фиксируется тестами.

## Документация и тесты

Модуль должен иметь:

- краткое описание ответственности;
- описание public API;
- список запрещённых пересечений;
- unit/integration tests для публичного поведения.

## Границы

- Модуль не дублирует соседний модуль.
- Общая логика выносится только при реальном повторном использовании.
- Новые зависимости и пересечения фиксируются в `docs/architecture/`.
- Если старый модуль остаётся как wrapper, он помечается deprecated и не получает новую бизнес-логику.

## Правило для изменений

Перед переносом логики нужно ответить:

- какой модуль владеет поведением;
- какой public API нужен;
- какие старые вызовы останутся wrapper'ами;
- какие тесты доказывают совместимость;
- какие документы обновлены.
