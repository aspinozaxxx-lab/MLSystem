# Правила модулей MLSystem

## Определение

Модуль MLSystem - отдельная папка в `mlsystem/src`, которая строго определенной зоной ответсвенности.

## public API
- Каждый модуль обязательно содержит `api.py` и по необходимости `contracts.py`.
- `contracts.py` — слой публичных контрактов. В нем должны быть только DTO, Enum/Literal, Protocol/ABC и публичные исключения. Никакой бизнес-логики, IO, импортов внутренних реализаций и создания конкретных объектов.
- `api.py` — тонкий публичный фасад модуля. В нем должны быть только функции входа и фабрики, которые валидируют минимальные входные параметры, собирают зависимости и сразу делегируют работу во внутренние реализации. Основная логика, алгоритмы и интеграции должны оставаться внутри приватных модулей.
- Внешний код использует только public API.
- Внутренние функции модуля не импортируются из других модулей, кроме тестов.
- Изменение public API требует архитектурного решения и согласования с пользователем.

## Модуль должен иметь \docs\architecture\[название модуля]_module.md в котором:
- Описание зоны ответственности.
- Все public API с описанием каждого параметра.
- список запрещённых пересечений.

## Границы
- Модуль не дублирует соседний модуль.
- Новые зависимости и пересечения фиксируются в `docs/architecture/`.
- Если два и более модуля нуждаются в одинаковом функционале, то ставиться вопрос о создании нового модуля.
